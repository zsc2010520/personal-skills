# 小红书浏览器发布

本技能只负责发布阶段。每日 JSON 须由用户提供，或已经在前置流程中生成并通过校验；本技能只读取 `title`、`content`、`tags`、`id` 和 `kind`，禁止重新生成、改写或使用聊天记录中的文案。

## 发布前

- 使用用户指定的每日 JSON 文件。未指定时从当前工作目录查找 `YYYY-MM-DD.json`；存在多个候选且无法确定时，询问用户选择。
- 每轮只取第一条 `used:false` 记录；确认绝对路径存在、素材类型与 `kind` 匹配，且当天没有重复记录。
- 图片进入图文入口，视频进入视频入口；只上传这一条记录对应的一个素材。
- 使用已登录的 Codex 内置浏览器（IAB）`creator.xiaohongshu.com` 标签页，不使用 Chrome、Edge 或 macOS 文件选择器，也不打开新的登录页。

## 编辑与强制校验

1. 用记录中的绝对路径上传，并核对缩略图/手机预览与目标素材一致，数量恰为一张。
2. 标题直接填 `title`；正文直接填 `content`。正文按句输入，每个 `。` 后真实回车，正文末尾另起独立话题行。
3. 只处理 JSON `tags` 中的话题；逐个输入并等待平台识别，确认蓝色结构化话题且 AX 出现 `[话题]`。不得添加推荐话题。
4. 开启原创声明；若出现须知，勾选并点击“声明原创”，确认页面出现“已声明原创”。
5. 默认只点击“暂存离开”，不点击“发布笔记”；保存成功且草稿标题可验证后，才可登记结果。

## 每条素材的固定执行顺序

1. 重新读取台账，取第一条 `used:false`，并在开始前核对素材绝对路径、标题、正文和完整 `tags`。
2. 仅绑定 Codex 内置浏览器的 IAB 标签页；先读取当前页面状态，不凭旧的 AX 编号或旧的标签页句柄操作。
3. 上传后确认 `1/18`、图片编辑器、目标缩略图/预览均已出现；上传事件失败时停下并重新读取页面，再重触发文件选择器，不改用系统文件对话框。
4. 填写标题和正文；正文句子之间使用真实回车，正文最后另起话题行。
5. 每个 JSON 话题单独输入，等待候选加载后选择精确匹配项。候选不存在时，按用户授权依次使用“新建话题”完成结构化话题。
6. 保存前逐个检查每个 JSON 话题的上下文确实包含 `[话题]#`。若任一话题只是普通文本，清空并重建整段话题区，重新逐个点亮；不得带着未点亮话题保存。
7. 完成原创声明并确认“已声明原创”。只点击“暂存离开”所在的白色保存区域，严禁点击红色“发布笔记”。
8. 看到“保存成功”且草稿箱能按标题和时间找到当前草稿后，才回写当前记录的 `used:true` 与 `draftSavedAt`。
9. 每完成一条，立即向用户输出固定报告：
   - `任务要求`：上传素材、填写 JSON 文案、点亮全部话题、原创声明、暂存草稿、禁止正式发布；
   - `已做检查项`：素材文件名、IAB 上传与 `1/18`、标题、正文换行、逐个话题 `[话题]#`、原创声明、草稿标题/保存时间、台账回写、未点击发布。
10. 报告完成后再进入下一条；任何一项无法确认都停在当前记录，不回写、不继续。

## 登记与停止

- 保存成功后，只在同一 JSON 记录中把 `used` 改为 `true` 并写入 `draftSavedAt`；不得新增其他状态字段，也不得覆盖 `id`、`location`、`kind`、`title`、`content` 或 `tags`。
- 上传、正文换行、话题、原创声明或保存任一项无法确认时，停在当前记录，不处理下一条、不登记。
- 用户指定“只处理 N 条”时，成功登记 N 条后立即停止。
- 任何“立即发布”按钮都禁止点击；任务要求定时发布时，也只能使用已核验的定时提交路径。

## 详细操作参考

本技能的上传、话题、原创声明和保存检查均按下述规范执行。

- 正文完成并核验换行后，将光标定位到正文末尾独立话题行。逐个输入 `#` 和当前话题文字，核对输入完整，再等待精确匹配候选并选择。每个话题转为结构化 `[话题]` 后再处理下一个。
- 候选不存在时，仅在用户已授权新建话题且页面提供该入口时创建。普通文本残留、话题插入句中或内容串位时，修复话题区后重新逐项核验。
- 保存前重新读取页面，确认单个目标素材、JSON 标题与正文、真实换行、全部结构化话题和“已声明原创”。保存状态不确定时先检查草稿箱，避免重复保存。

### 内置浏览器上传文件

- 内置浏览器上传时，不读取、导出或写入 Chrome Cookie；登录态以当前内置浏览器已打开且已登录的 `creator.xiaohongshu.com` 标签页为准。
- 每次开始、每次工具超时后，都以当前发布页 URL 直接绑定 Codex IAB，再枚举该 IAB 的当前标签页并重新获取句柄。IAB 与标签页的数字 ID 会在会话恢复后变化，禁止沿用历史 ID。
- 全局浏览器清单偶发读取失败时，优先按当前发布页 URL 直接绑定 IAB；直接绑定成功后，以该绑定返回的 IAB 和其当前标签页继续，不改用 Chrome、Edge，也不新开登录页。
- 日常状态核验使用轻量、针对性的定位器（例如“上传图片”按钮数、`1/18`、`图片编辑`、标题、`已声明原创`）。仅在需要从话题候选中选择精确项时读取 DOM 快照；避免在富编辑页面反复读取完整快照，以降低控制通道超时概率。
- 单次页面查询或交互超时时，不盲目重放上传、保存或发布动作。先重新绑定并检查页面是否已有该动作的可见证据；只有确认仍处于相应前置状态，才重新触发一次安全操作。
- 禁止通过拖拽、剪贴板或修改页面脚本伪造上传。应点击“上传图片”或“选择文件”，监听该标签页的 `filechooser` 事件，再对事件返回的 chooser 调用 `setFiles([绝对路径])`。这会把单个本机文件交给页面原生的 `<input type=file>`，由平台完成正常上传。
- 参考调用顺序（按当前 CUA/Playwright 运行时）：`const chooserPromise = page.playwright.waitForEvent('filechooser')` → 点击上传按钮 → `const chooser = await chooserPromise` → `await chooser.setFiles([assetAbsolutePath])`。
- 文件选择后必须等待上传稳定，并在页面确认：目标缩略图、手机预览及 `1/18`（单图）均出现。未见这些证据不得填写正文、保存草稿或登记 JSON。
- 需要重新选择素材时，重新触发一次 `filechooser`；不要复用过期 chooser、不要把多个文件传给单图记录。
- 内置浏览器运行时可能偶发首次点击不触发事件；允许在确认页面仍处于上传入口后重新监听并点击一次（必要时使用当前可见上传按钮的强制点击），但不得打开 Chrome、Edge 或 macOS 文件选择器。
- IAB 浏览器编号可能与外部 Chrome 编号不同。每次恢复会话先列出浏览器类型，选择 `type:"iab"` 的 Codex 内置浏览器及其当前标签页，禁止凭历史数字 ID 猜测。

### 固定完成报告模板

```text
已完成第 N 条（台账第 M 条）：

任务要求：读取 JSON 原文，上传单张素材，填写标题/正文，点亮全部 JSON 话题，完成原创声明，只暂存草稿，不正式发布。

已做检查项：
- 素材：文件名
- 上传位置：Codex 内置浏览器 IAB；页面显示 1/18
- 标题：已按 JSON 填写
- 正文：已按 JSON 填写并按句换行
- 话题：X/X 均核验为结构化 [话题]#
- 原创声明：已确认
- 保存：草稿箱标题与保存时间
- 台账：已写入 used:true 和 draftSavedAt
- 正式发布：未点击
```
